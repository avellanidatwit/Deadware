Getting started / 02

Your first survivor program

Write a rule. Watch a decision. Adapt your strategy.

1. Connect and observe

Open View and log in with your email and password. Use the dropdown to switch between your survivors and zombies. Check the selected entity status and use the grid key to read the map. The server keeps running while you observe.

2. Write a priority list

Open the Code page and choose Create a survivor. Name it, write its survivor script and prepare its zombie behavior. You can save both scripts to your library before injecting it. The example below explains how a survivor program works. This script approaches visible closed doors, opens them, and explores the revealed interior. It only scavenges when inventory has space. Each condition has one action underneath it. The first matching rule wins.

WHEN health < 40 AND hasItem bandage
    USE bandage

WHEN zombieNearby 1
    ATTACK zombie

WHEN zombieNearby 6
    MOVE_AWAY nearest zombie

WHEN thirsty AND hasItem water
    USE water

WHEN hungry AND hasItem food
    EAT food

WHEN hasItem weapon AND NOT equipped weapon
    EQUIP weapon

WHEN itemsOnFloor AND inventorySpace
    PICK_UP items

WHEN containerNearby AND inventorySpace
    SEARCH nearest container

WHEN doorNearby
    OPEN door

WHEN containerNearby 8 AND inventorySpace
    MOVE_TO nearest container

WHEN distance nearest door > 1
    MOVE_TO nearest door

OTHERWISE
    EXPLORE

3. Deploy and observe

Press Inject survivor to queue a new survivor at a random free location, or select an active entity and press Update behavior. Return to World view to observe it. When a survivor dies, it rises at its corpse using its zombie program; its scripts are archived in your library. Zombies cannot be injected directly. Survivor movement happens every second update; on other updates the script can select a later interaction. A failed action still takes an update.

4. Give needs a priority

The starter script places these rules above exploration and scavenging. Your survivor needs to find and carry the matching items first.

WHEN health < 40 AND hasItem bandage
    USE bandage

WHEN thirsty AND hasItem water
    USE water

WHEN hungry AND hasItem food
    EAT food

Use the Wiki to explore equipment, target selectors, memory, and Boolean conditions. Deployed scripts and world state persist on the server across browser refreshes and server restarts.
