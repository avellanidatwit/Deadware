Start with behavior, then learn SurvivorScript

Open Code, choose Create a survivor, and select Coward, Scavenger, Fighter, or Explorer in Behavior Builder. Custom starts with Explore. Change a rule, deploy, watch View, and return to adjust it. Draft edits only affect your survivor after you deploy.

  1. First rule: Add Rule. Choose Distance to ? nearest ? Zombie ? is at most ? 4 tiles. Choose Move away from ? nearest ? Zombie. Add OTHERWISE ? Explore.
  2. Priority: Add another rule: Zombie distance at most 1 tile ? Attack nearest Zombie. Move it above the flee rule. Rules are checked from top to bottom, and the first match wins.
  3. Needs: Choose Needs and health ? Hunger ? is above ? 70. Add Inventory contains ? Food. Match All conditions, then Eat ? Food. Higher hunger and thirst mean more urgent needs.
  4. Targeting: Compare nearest, weakest, and strongest Zombie. Weakest and strongest are available for living targets. Distance and search range are measured in tiles.
  5. Scavenging: Find ? Food approaches visible floor supplies or explores when none are visible. Pick up ? Food collects at the current position. Search ? Container interacts with an adjacent container; Move toward ? Container approaches it first. Searching does not automatically collect loot.
  6. Modes: Add scavenging, then fleeing. The first mode is the default. Add Nearby count ? Zombie ? within 6 tiles ? is at least 3, then Change mode to ? Fleeing. Next add Current mode ? is exactly ? Fleeing, then Move away from ? nearest Zombie. Add a higher rule that changes back to Scavenging when count Zombie within 6 tiles is exactly 0, so the survivor can leave that mode.

Memory has four named places: Home, Target, Last zombie, and Last container. Remember your current position as Home, or remember a nearby container as Target. Return to Home travels there; Patrol alternates between the chosen remembered destination and Home.

View generated SurvivorScript is optional. Switch to SurvivorScript whenever you want to type or paste rules. Mixed All/Any groups stay in the text editor so their meaning is preserved. Comments are preserved while switching views; editing a visual rule regenerates the script without comments.

Rule execution

Write WHEN followed by a condition and one action on the next line. Rules run top to bottom; the first eligible match wins. Put OTHERWISE last. With no matching rule, the entity waits. Commands are case-sensitive. Lines beginning with # are comments.

The server accepts 1-100 rules, up to 250 condition nodes across the whole script (each comparison, AND, OR, NOT and OTHERWISE counts as a node), 512 characters per line and 16 KiB per script. NOT binds before AND, then OR. Parentheses, loops and functions are not supported. All capabilities are unlocked.

A failed action consumes the decision. Check inventory and distance in your conditions. Impossible pickups and movement without enough stamina are skipped. Movement continues between decisions until replaced, blocked, or its target becomes unavailable.

Targets and conditions

Targets use [selector] type [range]. The selector defaults to nearest. Available selectors are nearest, farthest, weakest and strongest; the last two require an actor. Survivors see up to eight tiles; zombies use their detection range (five by default). Queries respect walls, doors, sight range and living status, and exclude the actor itself. An explicit range can narrow sight, never extend it.

Target types: zombie, survivor, container, car, door, building, food, water, bandage, weapon, gun, ammo, armor, home, target, lastZombie, lastContainer.

Movement

Survivors move at 1.0 tiles/second and zombies at 1.2. Pathfinding is server-controlled; survivors route through revealed terrain. MOVE north/south/east/west continues in that direction. EXPLORE searches revealed routes toward unexplored terrain; zombies roam. WAIT stops movement.

MOVE_TO nearest food approaches visible loot without picking it up. MOVE_TO nearest container stops in interaction range. MOVE_AWAY nearest zombie flees. FOLLOW nearest survivor follows an actor. Missing targets do not trigger exploration.

SPRINT MOVE_AWAY nearest zombie or SPRINT FIND water boosts survivor speed to 1.6 tiles/second for three seconds. Requires 20 stamina, costs 10 stamina per tile and has an eight-second cooldown measured from activation. Normal movement costs two stamina per tile; resting restores five per second.

Zombie programs

Zombies use the same visible, count, distance, health, mode and Boolean syntax. They can MOVE, MOVE_TO, MOVE_AWAY, FOLLOW, ATTACK, EXPLORE, WAIT and SET_MODE. Targeted zombie commands accept actors; attacks must target survivors. Inventory, needs, sprint, environmental interactions and coordinate memory are survivor-only.

WHEN distance nearest survivor <= 1
    ATTACK nearest survivor

WHEN count survivor 5 > 0
    MOVE_TO nearest survivor

OTHERWISE
    EXPLORE

Modes and example

Declare MODE names before any rules. The first is the initial mode. Use up to 16 unique names, starting with a lowercase letter and containing lowercase letters, digits or underscores (32 characters maximum). SET_MODE consumes one decision and stops the previous movement. The next decision evaluates the same priority list with the new mode. Modes persist through saves and reset to the first declaration when you deploy a program. With no MODE declarations, the entity has no mode and mode references are invalid. A dead survivor retains its last mode as inactive saved state. Its new zombie starts independently in the first mode of its zombie program, or with no mode if that program declares none. Deploying a new script always resets the mode, even if its names overlap; deploying a script without modes clears it. Zombies can use modes too.

MODE scavenging
MODE fleeing

WHEN health < 40 AND hasItem bandage
    USE bandage

WHEN mode != fleeing AND count zombie 5 > 0
    SET_MODE fleeing

WHEN mode == fleeing AND count zombie 8 == 0
    SET_MODE scavenging

WHEN mode == fleeing AND stamina >= 20
    SPRINT MOVE_AWAY nearest zombie

WHEN mode == fleeing
    MOVE_AWAY nearest zombie

WHEN thirst >= 80 AND hasItem water
    USE water

WHEN itemsOnFloor AND inventorySpace
    PICK_UP items

WHEN distance nearest container <= 1 AND inventorySpace
    SEARCH nearest container

WHEN distance nearest door <= 1
    OPEN nearest door

WHEN mode == scavenging AND itemCount water < 2 AND inventorySpace
    FIND water

OTHERWISE
    EXPLORE

Use count and distance for perception and numeric comparisons for needs. Older convenience conditions and commands are no longer accepted. Existing invalid deployed scripts wait until replaced; saved library text remains editable.
